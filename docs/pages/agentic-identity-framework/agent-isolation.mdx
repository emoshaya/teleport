## Sandboxing

-  hardware-level virtualization: "a separate guest kernel with a hypervisor
   boundary that untrusted code cannot cross" 
- "Ephemerality as a security property. Beams are explicitly designed to be
  short-lived (24h expiry, all supporting resources expire with them). This
  limits the blast radius of a compromised beam — credentials, delegation
  sessions, and the execution environment itself all disappear automatically.
  The "cattle not pets" naming philosophy reinforces this."

## Identity

- "Infrastructure identity — authenticating the components themselves. That's
  what mTLS, SSH certificates, SPIFFE X509-SVIDs, and WorkloadIdentity are
  doing. Each component (Envoy, tbot, the auth server) has a cryptographic
  identity that lets other components verify who they're talking to"
- "User identity delegation — the more distinctive piece. The beam doesn't just
  have its own identity; it inherits the human user's identity via the
  DelegationSession. This means the agent acts as the user, not as an anonymous
  compute job. Every resource access the agent makes is attributable to a
  specific person, with that person's permissions governing what's allowed.
  [...] That second piece is what separates Beams from a generic compute
  sandbox. A Firecracker microVM running in isolation with mTLS-authenticated
  connections is just secure infrastructure. The delegation mechanism is what
  makes the agent's identity meaningful in the context of the organization's
  access model — and it's also what makes audit possible, since there's a human
  identity to attribute actions to."
- "VNet is the mechanism that makes identity delegation practical. Without it,
  the agent would need to explicitly authenticate to each resource, which would
  mean either managing credentials itself or requiring human intervention. VNet
  intercepts connections transparently and attaches the delegated identity
  certificate at the point of access, so the delegation mechanism works without
  the agent's cooperation or awareness."

## Access controls

- Human users accessing a beam: roles encoded in certificate
- "For the agent acting inside the beam, it's the same mechanism but mediated
  through delegation. The DelegationSession generates a certificate for the
  agent that encodes the user's roles (or a subset of them, in future
  iterations). When the agent accesses a Teleport-protected resource via VNet,
  that certificate is presented, and the Auth Service checks its roles the same
  way it would for a human user."
